# Styling: BEM and a fixed set of tokens, without Tailwind and daisyUI

Status: **implemented (2026-10-30)**, see §7 and §8; to be checked in the browser. Part of the workbench
(`docs/2026-10-28-workbench.md`).

## 1. Context and goal

The workbench looks "off": controls of different heights, borders and corner radii side by side, defaults that fight the
layout. The cause is two styling systems at once:

- the workbench's own parts (rail, panels, bars, context menu, quick input, chart frame) are hand-written CSS with BEM
  classes (`dashica-wb__title-bar`), taking their colors from daisyUI's variables (`--color-base-200`);
- the extensions' controls are daisyUI components and Tailwind utilities in the markup
  (`btn btn-sm join-item border-base-300 bg-base-100 shadow-none`), every adjustment an override of daisyUI's defaults.

**Goal:** one system. Every element is styled by a BEM class in the CSS file next to its code; every value (color,
space, size, radius, …) is one of a fixed set of tokens. Tailwind, daisyUI and the Typography plugin are removed.

## 3. Proposed solution

### 3.1 Tokens: `frontend/core/style/tokens.css`

Custom properties on `:root`, the only place with raw values. Dark mode redefines the colors under
`@media (prefers-color-scheme: dark)`; everything else is shared.

| Group | Tokens | Values (light) |
|---|---|---|
| Surfaces | `--color-surface` (content), `--color-surface-subtle` (bars, panels), `--color-surface-raised` (controls, popovers) | `#fff`, `#f4f5f7`, `#fff` |
| Lines | `--color-border`, `--color-border-strong` | `#e1e4e8`, `#c9ced6` |
| Text | `--color-text`, `--color-text-muted`, `--color-text-on-accent` | `#1f2328`, `#656d76`, `#fff` |
| Accent | `--color-accent`, `--color-accent-subtle` (tint: active entry, selection) | `#2563eb`, `color-mix(… 12%)` |
| States | `--color-danger`, `--color-danger-subtle`, `--color-hover` | |
| Space | `--space-1` … `--space-8` | 4, 8, 12, 16, 24, 32px |
| Type | `--font-sans`, `--font-mono`; `--text-xs` 11, `--text-sm` 13, `--text-md` 14, `--text-lg` 16, `--text-xl` 20px; `--weight-normal` 400, `--weight-medium` 500, `--weight-bold` 600 | system font stack as today |
| Controls | `--control-height` 28px, `--control-padding-x` 8px | one size for all controls |
| Shape | `--radius-sm` 2px, `--radius-md` 4px; `--border-width` 1px | angular |
| Depth | `--shadow-popover`; `--z-popover`, `--z-overlay` | |
| Motion | `--duration-fast` 150ms | |

No component writes a raw color, size or radius; a check enforces it (§3.6). A token is added only when a value occurs
in several places.

### 3.2 Base: `frontend/core/style/base.css`

What preflight did and we rely on: `box-sizing: border-box`, no default margins, controls inheriting the font, lists
and buttons without browser styles, `body` with `--font-sans`, `--text-md`, `--color-text` on `--color-surface-subtle`
(replacing `bg-base-200` in `shell.go`).

### 3.3 Controls: `frontend/core/style/controls.css`

The few controls every part shares, as BEM blocks with modifiers (each with the prefix `d-`, §7: `d-button`):

| Block | Modifiers / elements | Replaces |
|---|---|---|
| `button` | `--ghost`, `--primary`, `--icon` (square, icon only), `--active` | `btn btn-sm btn-ghost btn-circle btn-primary btn-outline btn-active` |
| `segmented` | `__item` | `join join-item` |
| `field` | `--mono`, `--invalid`; on `input`, `select`, `textarea` | `input select textarea input-sm …-bordered` |
| `checkbox` | | `checkbox checkbox-sm` |
| `badge` | `--dot` | `badge badge-primary badge-xs` |
| `list` | `__heading`, `__item`, `__item--active` | `menu menu-sm menu-title menu-active` |
| `spinner` | | `loading loading-spinner` |
| `notice` | `--error` | `alert alert-error` |
| `kbd` | | `kbd` |

All controls are `--control-height` high, with `--radius-md` and one border style, so that they line up in a bar.

### 3.4 Components: one CSS file next to the code, one block each

- **Naming:** BEM, kebab-case, prefix `d-` (§7): `d-block__element--modifier`. The block is named after the component
  (`d-time-picker`, `d-filter-bar`, `d-dashboards-menu`, `d-chart-frame`, `d-record-details`, `d-sticky-tooltip`,
  `d-markdown`). The workbench's regions stay one block (`d-workbench__title-bar`, today `dashica-wb__…`). Today's mixed names (`stickyTooltip__…`,
  `record-details-panel`, `autoTable__…`) are renamed as their file is migrated.
- **Layout** inside a component (flex, gap, padding) goes into its block's CSS. There are no utility classes.
- **Markdown:** `markdown.css` styles the server's HTML under `.markdown` (headings, paragraphs, lists, tables, code,
  quotes), in place of the Typography plugin; about 80 lines.
- **Icons:** lucide icons get their size as attributes (`createElement(Clock, { width: 16, height: 16 })`), not as
  classes.
- **Tabulator** keeps its own CSS; only its font and font size follow the tokens.

### 3.5 Build

`frontendBuild.mjs` drops `esbuild-plugin-tailwindcss`: esbuild bundles the CSS imported from TS (as today for the
component files) into `public/dist/index.css`. `frontend/index.css` imports `tokens.css`, `base.css`, `controls.css`.
`package.json` loses `tailwindcss`, `daisyui`, `@tailwindcss/typography`, `esbuild-plugin-tailwindcss` (the user runs
`npm i`).

### 3.6 Checks

A quality task `.mise/tasks/quality/css` (next to `top-comments`), run by the user and in CI, fails on:

- a raw color (`#…`, `rgb(`, `hsl(`, a named color) or a raw `px` value of a tokened group outside `tokens.css`;
- a class in markup that no CSS file defines (catches leftover Tailwind / daisyUI classes and typos).

## 4. Migration

Done in one commit (decided 2026-10-30: "can be one big commit"); the steps below are its parts.

| # | Step |
|---|---|
| 1 | `tokens.css`, `base.css`, `controls.css` added and imported next to Tailwind; the workbench's CSS takes the tokens instead of `--color-base-*` / `--wb-*` |
| 2 | Title bar: time picker, refresh, filters (funnel, filter bar) |
| 3 | Dashboards menu, search everywhere |
| 4 | Page and widgets: dashboard page, grid, collapsible, chart frame, stats, form widgets (checkbox group, text input, Speedscope link) |
| 5 | Markdown: own styles in place of the Typography plugin |
| 6 | Table (`chart-library/table.ts`, `table.css`): search, record details, sticky tooltip |
| 7 | Debug panel, schema table, errors (`page-impl.ts`, `index.ts`), quick input, side bar, bottom panel |
| 8 | Removal: Tailwind, daisyUI and Typography out of `index.css`, `frontendBuild.mjs`, `package.json`; `shell.go` without the body class |
| 9 | The check (§3.6), and the concept checked off |

Tests that select by a daisyUI class (`.badge`, `.menu-active`, …) switch to the BEM class or, better, to a role or label
in the step that changes the markup.

## 5. Alternatives considered

- **Keep daisyUI, use it everywhere** (also for the workbench's own parts): less own CSS, but the defaults keep
  fighting the layout, and the look stays daisyUI's.
- **Keep Tailwind, drop only daisyUI:** utilities in the markup stay a second place where the look is decided; BEM with
  tokens puts it in one place per component.
- **CSS-in-TS (e.g. style objects):** no build step needed, but no `:hover`, media queries or cascade without a
  library; plain CSS files are what esbuild already bundles.

## 6. Risks

- **No browser in the sandbox:** every step needs the user's look (screenshot) before the next; Playwright specs would
  catch what breaks (§ the open coverage gap in the workbench concept).
- **Preflight gone:** spots that relied on it silently (a `ul` with bullets, a `button` with a gray background) show up
  only in the browser; `base.css` covers what is known.
- **Tabulator's light / midnight themes** have their own colors; they may not match the tokens exactly. Acceptable
  until the table is reconsidered (Perspective, workbench concept §6).
- **Size of the change:** ~25 TS and ~12 CSS files; done in the steps above, each small.

## 7. Decisions (2026-10-30)

1. **Prefix `d-`** (Dashica) on every block: `d-button`, `d-time-picker__panel`, `d-workbench__title-bar`. It keeps
   Dashica's classes apart from Tabulator's (`tabulator-…`), Plot's (`plot-…`) and the server's markdown HTML.
2. **Colors:** the values in §3.1 to start with, close to today's look (winter / night); they are adjusted in
   `tokens.css` alone once seen in the browser.
3. **Control size:** one, 28px, to start with; a second size only if a place turns out to need it.

## 8. As implemented (2026-10-30)

- `frontend/core/style/`: `tokens.css` (§3.1, plus `--color-success`, `--color-highlight` for the table's search,
  `--text-display` for the stats, `--icon-size`, `--shadow-overlay`, `--duration-slow`), `base.css`, `controls.css`
  (§3.3, plus `d-form-field` for the dashboards' text input and checkbox group).
- The workbench's regions are the block `d-workbench` (`d-workbench__title-bar`, …), its side's share
  `--d-workbench-right-side`; components have their own blocks (`d-time-picker`, `d-filter-bar`, `d-dashboards-menu`,
  `d-search-button`, `d-brand`, `d-chart-frame`, `d-collapsible`, `d-grid`, `d-dashboard-page`, `d-markdown`,
  `d-schema-table`, `d-debug`, `d-table`, `d-record-panel`, `d-sticky-tooltip`, `d-stats`, `d-widget-error`).
- The grid's gap: `NewGrid()` no longer sets `"4px"`; without `Gap()` a grid's widgets are 16px apart, as the page's.
- The check: `node .mise/tasks/quality/css` (raw colors and raw sizes outside `tokens.css`; classes whose block no
  stylesheet defines).
- After the first look (decided 2026-10-30): groups without the rule above, a hover row and the widget count while
  closed, closed groups 4px apart; Plot's tooltips on `--color-surface-raised` (`--plot-background`) with the
  border's outline, Plot's chart title as ours, its axes in `--font-sans` / `--text-xs`; the chart menu's dots
  thicker. Legends unchanged for now.
- Open: the look in the browser (light and dark), Tabulator's own themes next to the tokens, `npm i` after the
  removed packages.
